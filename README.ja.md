# OpenTalkType

`fn` キーを押しながら話すと、整った文章がいま入力していた場所にそのまま入ります。

[![CI](https://github.com/SammyLin/OpenTalkType/actions/workflows/ci.yml/badge.svg)](https://github.com/SammyLin/OpenTalkType/actions/workflows/ci.yml)

音声認識は Mac の中だけで動き、音声がマシンの外に出ることはありません。外に出るのは認識後のテキストだけで、
設定した言語モデルに送られ、句読点が付き、言いよどみが取れた読める文章になって戻ってきます。
アカウントも、こちら側のサーバーも、テレメトリもありません。

さらに、ほかのソフトウェアから呼び出せる唯一の macOS 向けオープンソース音声入力でもあります。
URL スキーム、App Intents、MCP サーバーの三つ。この節を最初に置いているのは、それがこのアプリを選ぶ理由だからです。

## 自動化

音声入力は、ほかのソフトウェアから呼び出せる一機能であるべきです。`fn` キーが通る処理と同じものに、
OpenTalkType は三つの入口を用意しています。

### MCP サーバー

`OpenTalkType --mcp` は stdio 上で動く画面なしの MCP サーバーです。ポートは一切開かず、
アプリ本体と同じコードが動くので、モデルはあなたの実際のモード、実際の辞書、実際の履歴を扱えます。

**設定 › Automation** で有効にしてから、MCP クライアントの設定に次を追加します。

```json
{
  "mcpServers": {
    "opentalktype": {
      "command": "/Applications/OpenTalkType.app/Contents/MacOS/OpenTalkType",
      "args": ["--mcp"]
    }
  }
}
```

設定 › Automation には、あなたの環境での実際のパスがコピーボタン付きで表示されます。ツールは四つです。

| ツール | 内容 |
|---|---|
| `opentalktype_clean_text` | 渡したテキストを任意のモードで整形処理にかける |
| `opentalktype_history_search` | 音声入力の履歴を新しい順に検索する |
| `opentalktype_add_term` | 用語と、その誤認識される綴りを辞書に追加する |
| `opentalktype_list_modes` | 定義済みのモードを id 付きで一覧する |

既定では無効で、それは意図的です。有効にすると、このバイナリを実行できるローカルのプロセスは
あなたの音声入力履歴すべてを読めるからです。

### URL スキーム

こちらも既定では無効です。この種のリンクはどんな Web ページからでも開けるためです。

```
opentalktype://start?mode=dictate         指定したモードで音声入力を開始
opentalktype://stop                       今回を終了し、整形して貼り付け
opentalktype://cancel                     今回を取り消す。貼らない、残さない
opentalktype://run?mode=dictate&text=…    マイクを使わず、このテキストを整形
opentalktype://paste-last                 直前の結果をもう一度貼り付け
```

Raycast、Keyboard Maestro、Stream Deck、あるいはシェルの `open` 一行で十分です。`mode` を省くと dictate、
存在しないモードを指定した場合は何も起きません。間違ったモードで黙って音声入力するよりましだからです。
`run` に渡せるテキストは 20,000 文字までです。

### App Intents

Start Dictation、Stop Dictation、Cancel Dictation、Clean Up Text、Add Dictionary Term が
ショートカット、Spotlight、その他 intent を読む場所すべてに現れます。Clean Up Text は整形後の文字列を返すので、
ショートカットの続きにそのままつなげられます。モードの引数は、実際に持っているモードから作られるピッカーです。
ここに有効・無効の切り替えはありません。intent は、あなたがショートカットに組み込んで実行したときだけ動きます。

### シェルアクション

各モードには `/bin/sh` のコマンドを持たせられます。テキストが整った時点で実行され、環境変数には
`$OT_TRANSCRIPT`、`$OT_MODE`、`$OT_APP`、`$OT_RAW` が入り、同じテキストが標準入力にも渡ります。
コマンドが何か出力すれば、それが貼り付けられるテキストになります。
この一つの欄で、モードは Webhook にも、メモへの追記にも、任意の API 呼び出しにもなります。
既定のコマンドはどこにもなく、自分で書くまで何もしません。

## モード

標準で三つ。押しながら話し、離すと送られます。

| モード | キー | 動作 |
|---|---|---|
| Dictate | `fn` を押しながら | 話した内容を整形してカーソル位置に挿入 |
| Translate | `fn` + 左 `⇧` | ある言語で話し、別の言語の自然な文章を得る |
| Ask | `fn` + `space` | 選択中のテキストへの指示を話し、結果で置き換える |

`fn` を素早く 2 回叩くとマイクが入りっぱなしになり、両手が空きます。もう一度叩けば終了。
`Esc` はその回を丸ごと破棄します。認識も貼り付けも保存もしません。

モードは固定のリストではなくレコードです。設定 › Modes で、名前、アイコン、システムプロンプト、
組み合わせるキー、シェルコマンドを自分で決めて追加できますし、標準の三つもプロンプトごと編集できます。
ホットキー、上記三つの自動化の入口、MCP のモード一覧、アプリごとのルール、すべてが同じテーブルを見ています。

## Mac の外に出るもの

録音と認識には macOS 26 の `SpeechAnalyzer` を通じて Apple のオンデバイス音声モデルを使います。
音声がアップロードされることはなく、言語モデルのダウンロードが済めば認識にネットワークは不要です。

外に出るもの、そして出る唯一のものは、認識が終わったテキストです。整形のために、選んだプロバイダに送られます。

| プロバイダ | 備考 |
|---|---|
| DeepSeek（既定） | 実測で約 1 秒、中国語の品質が高く、非常に安価 |
| Claude Code（ローカル CLI） | **API キー不要。** すでにサインイン済みの Claude Code のセッションを使います。CLI が毎回コールドスタートするため約 5 秒 |
| Anthropic、OpenAI、Gemini | 自分の API キー。macOS キーチェーンに保存されます |
| Local | この Mac 上の OpenAI 互換サーバー（Ollama、LM Studio など）。何一つマシンの外に出ません |

ほかのネットワーク通信は更新確認だけです。新しいバージョンがあるかを尋ねるだけで、既定ではオフ、さらに「アプリケーション」フォルダ以外から実行している場合は確認そのものを行いません。

## 辞書

認識エンジンは固有名詞を必ず崩します。同僚の名前、製品名、社内システム、コマンド名が間違って出てくるのを
止めるための仕組みが辞書で、中国語と英語が混じった発話が実用になるのもこれのおかげです。
中国語の文の中に英語の術語が三つ混じっていても、その三つはあなたの綴りどおりに出ます。

一件は「正しい綴り」と「代わりに認識される綴り」の組です。使われ方は三通りで、モデルが見る前の文字列置換、
システムプロンプトに貼り込む確定リスト、そして DictationTranscriber エンジンを選んだときの認識側への語彙ヒントです。
置換は必ず単純な部分一致で、`\b` を使う単語境界の正規表現ではありません。漢字と漢字の間に単語境界はなく、
それでは機能そのものが無意味になるからです。

辞書は自分で育ちます。どちらの経路もテキストを貼り付けたあとに走るので、待ち時間は増えません。

- **対応づけ。** 整形後に現れた、実際には言っていない語は修正です。それが置き換えた崩れた文字列と組にして
  保存されるので、次に同じものが出たときはモデルに渡る前の置換で直ります。
- **モデルに尋ねる。** 整形済みのテキストを見せて、含まれる固有名詞と技術用語を挙げさせます。
  効くのはこちらです。モデルが毎回黙って間違える語はそもそも修正されないので、差分だけでは永遠に学べません。

自動追加された項目には印が付き、ほかと同じように編集も削除もできます。認識が最初から正しく綴った語は
追加されないので、一覧が膨れません。まるごと止めたい場合は設定 › General で。

## そのほか

- **履歴**は SQLite に保存され、検索でき、保持期間を設定できます（既定 30 日、無期限も可）。
  録音は希望した場合だけ残り、独自のスケジュールで削除されます。
- **置換ルール**はモデルのあとに走ります。文字列でも正規表現でも書け、順番も決まっています。
  辞書はモデルの前なのでモデルに覆されますが、こちらは覆されません。
- **アプリ・サイトごとのルール。**「このアプリでは、あるいはこのサイトでは、あのモードを使う」。
  サイトは最前面のブラウザウィンドウから読み取り、ブラウザごとのスクリプトは不要です。
- **HUD** はディスプレイのノッチ、画面下部、あるいは非表示から選べます。
- **挿入方法**は貼り付けか、疑似タイピングか。後者は合成 `⌘V` を無視する端末やゲームエンジン向けです。
  末尾スペースの追加、Return での送信はモードごとに設定できます。クリップボードは後で元に戻ります。
- **オーディオ**は入力デバイスの選択、無音での自動停止、録音中のほかの音のミュートに対応します。
- **バックアップ**はモード、辞書、置換ルール、アプリのルール、環境設定を 1 つの JSON に書き出します。
  API キー（キーチェーンにあります）も履歴も含まれません。
- インターフェースは 6 言語。うちネイティブが書いたのは 1 言語だけです。
  [CONTRIBUTING.md](CONTRIBUTING.md) を参照してください。

## インストール

**macOS 26 以降、Apple シリコン**が必要です。古い環境向けの代替はありません。
認識に使う `SpeechAnalyzer` が macOS 26 より前には存在しないためです。

1. [Releases](https://github.com/SammyLin/OpenTalkType/releases) から `.dmg` をダウンロードし、
   アプリケーションフォルダにドラッグします。
2. このビルドは **公証（notarization）を受けていません**。そのため初回は macOS が起動を拒みます。
   アプリを右クリックして「開く」を選ぶか、次を実行してください。
   ```sh
   xattr -d com.apple.quarantine /Applications/OpenTalkType.app
   ```
3. 求められたらマイクとアクセシビリティを許可します。
4. システム設定 › キーボード ›「地球儀キーを押して」を「何もしない」に設定します。
   そうしないと `fn` を押した瞬間、音声入力の上に絵文字ピッカーが開きます。

各リリースには `SHA256SUMS.txt` が付いているので、ダウンロードの検証に使えます。

## 正直に言っておくこと

**公証されていません。** 公証には有料の Apple Developer アカウントが必要で、このプロジェクトはまだ持っていません。
理由はそれだけで、影響するのは初回起動だけです。更新も自動ではインストールされません。
初回インストール後の更新は検証されます。各リリースは EdDSA 鍵で署名され、その鍵は作者のキーチェーンと このリポジトリの Actions secrets にのみ存在します。アプリはバンドルに埋め込まれた公開鍵と一致しないものを拒否するため、配布サーバーを掌握した相手でも更新を差し替えることはできません。自動確認は既定でオフです。
入れるかどうかはあなたが決めます。アクセシビリティ権限を持つアプリが未検証のビルドを自動で入れるのは
利便性ではなくキーロガーの配送経路なので、意図的にそうしていません。

**アクセシビリティ権限とは、実質的にすべてのキー入力を観測できる権限です。** `CGEvent` タップとはそういうもので、
そもそも `fn` はそれ以外の方法では検出できません。同じ権限が Ask モードの選択テキスト読み取りと
結果の貼り付けにも使われます。これを README の言葉だけで信用すべきではありません。
使っているコードは 1 ファイル、[`OpenTalkType/Input.swift`](OpenTalkType/Input.swift) だけで、
タップのコールバックは状態を切り替える以外何もせず、アプリには `LLM.swift` と更新確認の外に通信コードがありません。

**地球儀キーは「何もしない」にしてください。** そうするまでは、`fn` を押した瞬間に絵文字ピッカーも一緒に開きます。
アプリはあえて `fn` イベントを飲み込みません。WindowServer は event tap より上流で修飾キーの状態を更新するため、
握り潰すとシステム全体が `fn` を押しっぱなしだと思い込んでしまいます。

**ビルドし直すとアクセシビリティ権限が黙って無効になります。** ローカルビルドは ad-hoc 署名で、
ビルドのたびに識別子が変わるため、macOS は何も言わずに許可を無効化します。
それでいてシステム設定のチェックは入ったままに見えます。症状は「貼り付けだけが動かなくなる」です。
設定 › Permissions の「権限を再要求」で直すか、アクセシビリティの一覧から削除して追加し直してください。

**セキュア入力中は貼り付けできません。** パスワード欄や、ターミナルのセキュアキーボード入力が有効なとき、
システム全体がセキュア入力状態になり、合成イベントは一切届きません。
このときテキストはクリップボードに残り、アプリは壊れたふりをせず状況を説明します。

## ソースからビルド

サードパーティ依存なし、パッケージマネージャの手順なし、解決するものもありません。

```sh
xcodegen generate
open OpenTalkType.xcodeproj
```

xcodegen が未導入なら先に `brew install xcodegen` を。ビルドには Xcode 26 が必要です。
署名は ad-hoc なので、Apple Developer アカウントは要りません。

### セルフテスト

GUI はソースを読むだけでは検証できないので、アプリ自身がテストハーネスになっています。

```sh
OpenTalkType.app/Contents/MacOS/OpenTalkType --selftest
```

純粋なロジックの検査が 173 項目。ウィンドウも、マイクも、ネットワークも、権限要求もありません。
1 行につき `PASS` か `FAIL` を出力し、すべて通ったときだけ終了コード 0 を返します。
CI は push のたびに `macos-26` 上でこれを実行し、あわせて stdio サーバーに対する実際の MCP ハンドシェイクも行います。
リリースのワークフローでは、`.dmg` の中の実バイナリに対してもう一度実行されます。
