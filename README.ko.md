# OpenTalkType

`fn` 키를 누른 채 말하면, 정리된 문장이 방금 타이핑하던 자리에 그대로 들어갑니다.

[![CI](https://github.com/SammyLin/OpenTalkType/actions/workflows/ci.yml/badge.svg)](https://github.com/SammyLin/OpenTalkType/actions/workflows/ci.yml)

음성 인식은 Mac 안에서만 돌아가며 음성은 기기를 떠나지 않습니다. 밖으로 나가는 것은 인식된 텍스트뿐이고,
설정한 언어 모델로 보내져 문장부호가 붙고 군더더기가 빠진, 그대로 쓸 수 있는 문장이 되어 돌아옵니다.
계정도, 우리 쪽 서버도, 텔레메트리도 없습니다.

또한 다른 소프트웨어가 호출할 수 있는 유일한 macOS 오픈소스 받아쓰기 앱이기도 합니다.
URL 스킴, App Intents, MCP 서버 세 가지 모두 제공합니다. 이 절을 맨 앞에 둔 이유는, 그것이 이 앱을 고를 이유이기 때문입니다.

## 자동화

받아쓰기는 다른 소프트웨어가 호출할 수 있는 하나의 기능이어야 합니다. `fn` 키가 지나는 그 파이프라인에
OpenTalkType은 세 개의 문을 열어 두었습니다.

### MCP 서버

`OpenTalkType --mcp`는 stdio 위에서 도는 화면 없는 MCP 서버입니다. 포트를 전혀 열지 않고,
앱 본체와 같은 코드가 돌기 때문에 모델은 실제 모드, 실제 사전, 실제 기록을 다룹니다.

**설정 › Automation**에서 켠 다음, MCP 클라이언트 설정에 아래를 추가하세요.

```json
{
  "mcpServers": {
    "opentalktype": {
      "command": "/Applications/OpenTalkType.app/Contents/MacOS/OpenTalkType",
      "args": ["--mcp"]
    }
  }
}
```

설정 › Automation에는 사용자의 실제 경로가 복사 버튼과 함께 표시됩니다. 제공되는 도구는 네 개입니다.

| 도구 | 하는 일 |
|---|---|
| `opentalktype_clean_text` | 넘긴 텍스트를 원하는 모드의 정리 파이프라인에 통과시킴 |
| `opentalktype_history_search` | 받아쓰기 기록을 최신순으로 검색 |
| `opentalktype_add_term` | 용어와, 그것이 잘못 인식되는 철자를 사전에 추가 |
| `opentalktype_list_modes` | 정의해 둔 모드를 id와 함께 나열 |

기본값은 꺼짐이며, 의도적입니다. 켜면 이 바이너리를 실행할 수 있는 로컬 프로세스가
받아쓰기 기록 전체를 읽을 수 있기 때문입니다.

### URL 스킴

이것도 기본은 꺼짐입니다. 이런 링크는 어떤 웹 페이지에서든 열 수 있기 때문입니다.

```
opentalktype://start?mode=dictate         지정한 모드로 받아쓰기 시작
opentalktype://stop                       이번 세션을 끝내고 정리해서 붙여넣기
opentalktype://cancel                     취소: 붙여넣지 않고 남기지도 않음
opentalktype://run?mode=dictate&text=…    마이크 없이 이 텍스트만 정리
opentalktype://paste-last                 직전 결과를 다시 붙여넣기
```

Raycast, Keyboard Maestro, Stream Deck, 또는 셸의 `open` 한 줄이면 충분합니다. `mode`를 빼면 dictate이고,
없는 모드를 지정하면 아무 일도 하지 않습니다. 엉뚱한 모드로 조용히 받아쓰는 것보다 낫기 때문입니다.
`run`에 넘기는 텍스트는 20,000자까지입니다.

### App Intents

Start Dictation, Stop Dictation, Cancel Dictation, Clean Up Text, Add Dictionary Term이
단축어, Spotlight, 그 밖에 intent를 읽는 모든 곳에 나타납니다. Clean Up Text는 정리된 문자열을 반환하므로
단축어의 다음 단계로 그대로 이어집니다. 모드 매개변수는 실제로 가지고 있는 모드로 채워진 선택 목록입니다.
여기에는 켜고 끄는 스위치가 없습니다. intent는 사용자가 단축어에 넣고 실행했을 때만 동작하기 때문입니다.

### 셸 액션

모든 모드는 `/bin/sh` 명령을 하나 가질 수 있습니다. 텍스트가 준비되면 실행되며, 환경 변수로
`$OT_TRANSCRIPT`, `$OT_MODE`, `$OT_APP`, `$OT_RAW`가 들어가고 같은 텍스트가 표준 입력으로도 전달됩니다.
명령이 무언가를 출력하면 그 출력이 붙여넣을 텍스트가 됩니다.
이 한 칸으로 모드는 웹훅이 되고, 메모에 덧붙이는 도구가 되고, 어떤 API 호출도 됩니다.
기본 명령은 어디에도 없으며, 직접 적기 전에는 아무것도 하지 않습니다.

## 모드

기본 세 개. 누른 채 말하고, 떼면 전송됩니다.

| 모드 | 키 | 하는 일 |
|---|---|---|
| Dictate | `fn` 누른 채 | 말한 내용을 정리해 커서 위치에 삽입 |
| Translate | `fn` + 왼쪽 `⇧` | 한 언어로 말하고, 다른 언어의 자연스러운 문장을 받음 |
| Ask | `fn` + `space` | 선택한 텍스트에 대한 지시를 말하면 결과가 그 자리를 대체 |

`fn`을 두 번 빠르게 누르면 마이크가 켜진 채 고정되어 두 손이 자유로워집니다. 한 번 더 누르면 종료됩니다.
`Esc`는 그 세션을 통째로 버립니다. 인식도, 붙여넣기도, 저장도 하지 않습니다.

모드는 고정된 목록이 아니라 하나하나의 레코드입니다. 설정 › Modes에서 이름, 아이콘, 시스템 프롬프트,
함께 누를 키, 셸 명령을 직접 정해 추가할 수 있고, 기본 세 개도 프롬프트까지 수정할 수 있습니다.
단축키, 위의 자동화 세 통로, MCP의 모드 목록, 앱별 규칙이 모두 같은 테이블을 봅니다.

## Mac을 떠나는 것

녹음과 인식은 macOS 26의 `SpeechAnalyzer`를 통해 Apple의 온디바이스 음성 모델을 사용합니다.
음성은 업로드되지 않으며, 언어 모델을 내려받고 나면 인식에 네트워크가 전혀 필요 없습니다.

떠나는 것, 그리고 떠나는 유일한 것은 인식이 끝난 텍스트입니다. 정리를 위해 선택한 제공자로 보내집니다.

| 제공자 | 설명 |
|---|---|
| DeepSeek (기본값) | 실측 약 1초, 중국어 품질이 좋고 매우 저렴 |
| Claude Code (로컬 CLI) | **API 키가 전혀 필요 없음.** 이미 로그인된 Claude Code 세션을 그대로 사용. 매 요청마다 CLI가 콜드 스타트하므로 약 5초 |
| Anthropic, OpenAI, Gemini | 본인의 API 키. macOS 키체인에 보관됨 |
| Local | 이 Mac 위의 OpenAI 호환 서버(Ollama, LM Studio 등). 아무것도 기기를 떠나지 않음 |

그 밖의 네트워크 통신은 업데이트 확인뿐입니다. 새 버전이 있는지 묻는 것이 전부이며, 기본값은 꺼짐이고 응용 프로그램 폴더 밖에서 실행 중이면 확인 자체를 하지 않습니다.

## 사전

인식 엔진은 이름을 반드시 망가뜨립니다. 동료 이름, 제품명, 사내 시스템, 명령어가 계속 틀리게 나오는 것을
멈추는 장치가 사전이고, 중국어와 영어가 섞인 발화가 실용적이 되는 것도 이 덕분입니다.
중국어 문장 안에 영어 용어가 세 개 섞여 있어도, 그 세 개는 사용자가 쓰는 철자 그대로 나옵니다.

한 항목은 "올바른 철자"와 "대신 인식되는 철자들"의 짝입니다. 쓰이는 곳은 세 군데로,
모델이 보기 전의 문자열 치환, 시스템 프롬프트에 붙는 확정 목록, 그리고 DictationTranscriber 엔진을 골랐을 때
인식기 자체에 주는 어휘 힌트입니다. 치환은 항상 단순 부분 문자열 방식이며 `\b` 같은 단어 경계 정규식이 아닙니다.
한자와 한자 사이에는 단어 경계가 없어서, 그렇게 만들면 기능 자체가 무의미해지기 때문입니다.

사전은 스스로 자랍니다. 두 경로 모두 텍스트가 이미 붙여넣어진 뒤에 돌기 때문에 대기 시간은 늘지 않습니다.

- **짝짓기.** 정리 결과에 나타났지만 실제로는 말하지 않은 단어는 교정입니다. 그것이 대체한 뭉개진 문자열과
  짝지어 저장되므로, 다음번에는 모델이 개입하기 전 치환 단계에서 바로잡힙니다.
- **모델에게 묻기.** 정리된 텍스트를 보여 주고 그 안의 고유명사와 기술 용어를 묻습니다.
  실제로 효과가 있는 쪽은 이쪽입니다. 모델이 매번 조용히 틀리는 단어는 애초에 교정되지 않으므로,
  비교만으로는 영원히 배울 수 없습니다.

자동으로 추가된 항목에는 표시가 붙고, 다른 항목과 똑같이 수정하거나 지울 수 있습니다.
인식기가 이미 올바르게 적은 단어는 추가되지 않아 목록이 지저분해지지 않습니다.
전부 끄고 싶다면 설정 › General에서 끕니다.

## 그 밖에

- **기록**은 SQLite에 저장되고 검색할 수 있으며 보관 기간을 설정할 수 있습니다(기본 30일, 무기한도 가능).
  녹음은 원할 때만 남고 자체 일정에 따라 삭제됩니다.
- **치환 규칙**은 모델 뒤에 적용됩니다. 문자열이든 정규식이든 가능하고 순서도 정해집니다.
  사전은 모델 앞이라 모델이 되돌릴 수 있지만, 이쪽은 되돌려지지 않습니다.
- **앱·사이트별 규칙.** "이 앱에서는, 또는 이 사이트에서는 저 모드를 쓴다."
  사이트는 맨 앞 브라우저 창에서 읽어 오며 브라우저마다 스크립트를 쓸 필요가 없습니다.
- **HUD**는 디스플레이 노치, 화면 아래, 또는 표시하지 않음 중에서 고릅니다.
- **삽입 방식**은 붙여넣기 또는 가상 타이핑입니다. 후자는 합성 `⌘V`를 무시하는 터미널이나 게임 엔진용입니다.
  끝에 공백 추가, Return으로 전송은 모드별로 설정합니다. 클립보드는 나중에 원래대로 복원됩니다.
- **오디오**는 입력 장치 선택, 무음 시 자동 정지, 녹음 중 다른 소리 음소거를 지원합니다.
- **백업**은 모드, 사전, 치환 규칙, 앱 규칙, 환경설정을 하나의 JSON으로 내보냅니다.
  API 키(키체인에 있습니다)도, 받아쓰기 기록도 들어 있지 않습니다.
- 인터페이스는 7개 언어(English, 正體中文, 日本語, 한국어, Deutsch, Español, Français)이며 그중 원어민이 쓴 것은 하나뿐입니다.
  [CONTRIBUTING.md](CONTRIBUTING.md)를 참고하세요.

## 설치

**macOS 26 이상, Apple 실리콘**이 필요합니다. 구형 시스템을 위한 대체 경로는 없습니다.
인식에 쓰는 `SpeechAnalyzer`가 macOS 26 이전에는 존재하지 않기 때문입니다.

1. [Releases](https://github.com/SammyLin/OpenTalkType/releases)에서 `.dmg`를 내려받아 앱을
   응용 프로그램 폴더로 끌어다 놓습니다.
2. 마운트된 디스크 이미지가 아니라 응용 프로그램 폴더에서 실행하세요. 이미지는 읽기 전용이라
   거기서 실행한 앱은 자기 자신의 업데이트를 설치할 수 없습니다.
3. 요청이 뜨면 마이크와 손쉬운 사용 권한을 허용합니다.
4. 시스템 설정 › 키보드 › "지구본 키를 눌러서"를 "아무 작업 안 함"으로 바꿉니다.
   그러지 않으면 `fn`을 누르는 순간 받아쓰기 위로 이모지 선택기가 열립니다.

앱 자체는 무료입니다. 비용이 든다면 텍스트를 정리하는 언어 모델 쪽이고, 그 값은 직접 고른
제공자에게 바로 지불합니다. 여기에는 계정도 없고, 우리 쪽 서버를 거치는 것도 없습니다.
돈이 들지 않는 선택지도 둘 있습니다. Claude Code는 이미 가지고 있는 구독을 그대로 쓰고,
로컬 Ollama나 LM Studio는 전기요금만 듭니다.

각 릴리스는 Developer ID 인증서로 서명하고 Apple의 공증을 받아 티켓을 첨부하므로 첫 실행도
평범하게 됩니다. `spctl`이 받아들이지 않는 것은 릴리스 절차가 배포를 거부합니다.
모든 릴리스에는 `SHA256SUMS.txt`도 함께 올라가므로 내려받은 파일을 검증할 수 있습니다.

## 미리 밝혀 두는 거친 부분

**업데이트는 스스로 설치됩니다. 그리고 그것은 의심해 볼 만한 일입니다.**
첫 설치 이후의 업데이트는 이와 별개로 검증됩니다. 각 릴리스는 EdDSA 키로 서명되며, 그 키는 제작자의 키체인과 이 저장소의 Actions secrets에만 존재합니다. 앱은 번들에 포함된 공개 키와 일치하지 않는 것을 거부하므로, 배포 서버를 장악한 사람이라도 업데이트를 바꿔치기할 수 없습니다. 자동 확인은 기본적으로 꺼져 있습니다.
손쉬운 사용 권한을 가진 앱이 검증되지 않은 빌드를 자동으로 설치하는 것은 편의가 아니라
키로거 배포 경로이므로, 의도적으로 하지 않습니다.

**손쉬운 사용 권한은 사실상 모든 키 입력을 관찰할 수 있는 권한입니다.** `CGEvent` 탭이란 원래 그런 것이고,
`fn`은 그 방법이 아니면 감지할 수도 없습니다. 같은 권한이 Ask 모드에서 선택 텍스트를 읽고 결과를
붙여넣는 데도 쓰입니다. 이런 것을 README의 말만 믿고 넘어가서는 안 됩니다.
그 권한을 쓰는 코드는 파일 하나, [`OpenTalkType/Input.swift`](OpenTalkType/Input.swift)뿐이고,
탭 콜백은 상태를 바꾸는 일 외에 아무것도 하지 않으며, 앱에는 `LLM.swift`와 업데이트 확인 밖에
네트워크 코드가 없습니다.

**지구본 키를 "아무 작업 안 함"으로 설정하세요.** 그러기 전에는 `fn`을 누르는 순간 이모지 선택기가 함께 열립니다.
앱은 일부러 `fn` 이벤트를 삼키지 않습니다. WindowServer는 event tap보다 상류에서 수정자 키 상태를 갱신하므로,
가로채면 시스템 전체가 `fn`이 계속 눌려 있다고 믿게 됩니다.

**다시 빌드하면 손쉬운 사용 권한이 조용히 무효가 됩니다.** 로컬 빌드는 ad-hoc 서명이라 빌드할 때마다
식별자가 바뀌고, macOS는 아무 말 없이 허가를 무효화합니다. 그런데도 시스템 설정의 체크는 켜진 것처럼 보입니다.
증상은 붙여넣기만 갑자기 되지 않는 것입니다. 설정 › Permissions의 "권한 다시 요청"으로 고치거나,
손쉬운 사용 목록에서 앱을 지웠다가 다시 추가하세요.

**보안 입력 중에는 붙여넣을 수 없습니다.** 암호 입력란이나 터미널의 보안 키보드 입력이 켜져 있으면
시스템 전체가 보안 입력 상태가 되어 합성 이벤트가 전혀 전달되지 않습니다.
이때 텍스트는 클립보드에 남고, 앱은 고장 난 척하는 대신 무슨 일이 일어났는지 알려 줍니다.

## 소스에서 빌드

```sh
xcodegen generate
open OpenTalkType.xcodeproj
```

서드파티 의존성은 [Sparkle](https://github.com/sparkle-project/Sparkle) 하나뿐이며, Xcode에서
프로젝트를 열면 Swift Package Manager가 해결합니다. 이 예외에는 이유가 있습니다. 업데이터의
가치는 zip을 내려받는 데 있지 않고, 손쉬운 사용 권한을 가진 프로그램을 무언가가 교체하기 전에
서명을 검증하는 데 있기 때문입니다. 나머지는 모두 Apple의 프레임워크와 `libsqlite3`입니다.

xcodegen이 없다면 먼저 `brew install xcodegen`. 빌드에는 Xcode 26이 필요합니다.
서명은 ad-hoc이므로 Apple Developer 계정은 필요 없습니다.

### 셀프 테스트

GUI는 소스를 읽는 것만으로 검증할 수 없으므로, 앱 자체가 테스트 하네스입니다.

```sh
OpenTalkType.app/Contents/MacOS/OpenTalkType --selftest
```

순수 로직 검사 173개. 창도, 마이크도, 네트워크도, 권한 요청도 없습니다.
한 줄에 `PASS` 또는 `FAIL`을 출력하고, 전부 통과했을 때만 종료 코드 0을 반환합니다.
CI는 푸시할 때마다 `macos-26`에서 이것을 실행하고, stdio 서버에 대한 실제 MCP 핸드셰이크도 함께 수행합니다.
릴리스 워크플로에서는 `.dmg` 안의 실제 바이너리에 대해 한 번 더 실행합니다.
